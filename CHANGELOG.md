# Changelog

## [1.0.0](https://github.com/diareuse/spike/compare/0.0.15...1.0.0) (2026-10-17)


### ⚠ BREAKING CHANGES

* **core:** @Include(bindAs = Api::class) no longer compiles. Declare the binding instead, e.g.
* **compiler:** a graph that requests a type passed in more than once (two factory parameters, a parameter and an @Export member, or two @Export members of that type) no longer compiles. Keep one input, stop requesting the type, or qualify the inputs with a @spike.Qualifier annotation.
* **compiler:** a graph where an @EntryPoint.Factory parameter or an @Export member has the same type as an @Include binding no longer compiles. Remove the @Include, stop passing the value in, or qualify one of them with a @spike.Qualifier annotation.
* **core:** using @EntryPoint.Factory.SharesSingletons outside generated code is a compile error unless the file opts in to @InternalSpikeApi.
* **compiler:** requesting a Map multibinding with the wrong key type is a compile error instead of a warning and an empty map.
* **androidx:** DependencyFactory now takes a SingletonHolder constructor argument and generated X_DependencyHolderN classes no longer own one, so code generated by earlier compiler versions must be regenerated.
* **compiler:** @Singleton instances are no longer shared between entry point instances. Code that created several entry points and relied on them sharing a singleton must reuse one entry point. Generated DependencyHolderN classes no longer have a companion object.
* **compiler:** a declaration with bindTo (Set, List or Map) contributes only to its multibinding and is no longer injectable by its plain type, matching ViewModels and Dagger's @IntoSet/@IntoMap. Previously such entries also leaked into the root graph and made their type ambiguous.
* releases after 0.0.15 are licensed under MPL-2.0 instead of GPL-v3.
